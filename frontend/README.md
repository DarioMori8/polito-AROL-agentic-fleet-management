# Frontend

Mobile-first PWA for AROL plant operators and technicians: log in, scan a machine's QR code, chat with the AI assistant and read the machine's manual. The UI follows the **AROL Rugged UI** style: high contrast and touch targets of at least 48 px, usable with gloves.

## Tech stack

| Layer | Library |
|---|---|
| Framework | React 19 + Vite 8 |
| Routing | React Router 8 |
| PWA | `vite-plugin-pwa` (manifest, service worker with `autoUpdate`) |
| PDF viewer | `react-pdf` 10 |
| Markdown | `react-markdown` + `remark-gfm` |
| QR scanner | `html5-qrcode` |
| Icons | `lucide-react` |
| Component docs and tests | Storybook 10, Vitest + Playwright |
| Production server | Nginx (multi-stage Dockerfile) |

## Routes

| Path | Page | Access |
|---|---|---|
| `/login` | `LoginPage` | public |
| `/`, `/fleet` | `FleetView`: the machines of the user's company | login required, guests redirected to `/login` |
| `/scanner` | `MachineScanner`: QR scan with the camera | public |
| `/machine/:id` | `LandingResolver` → `LandingQR`: machine card | public; logs in as guest if the URL has QR credentials |
| `/workspace/:id` | `WorkspaceWrapper` → `ChatWorkspace`: chat + manual viewer | public; the chat needs a non-guest login |

The backend enforces the real access rules (company and visibility); the frontend only hides what the user cannot use.

## How it talks to the backend

All calls go to `VITE_API_URL` (default `http://localhost:8000`) with `credentials: "include"`, so the session cookie `arol_session` is sent automatically.

| Feature | Endpoint |
|---|---|
| Login / current user / logout | `POST /v1/sessions`, `GET` and `DELETE /v1/sessions/current` |
| Fleet and machine | `GET /v1/machines`, `GET /v1/machines/{id}` |
| Manual | `GET /v1/machines/{id}/manual`, PDF from `GET /v1/manuals/{id}/file` |
| Chat | `POST /v1/chat/stream` (SSE) |
| Conversation history | `GET /v1/conversations?machine_id=…`, `GET /v1/conversations/{id}/messages` |

**Guest login from a QR code.** A machine QR points to `/machine/<id>?u=<guest email>&k=<guest password>`. If no session exists, `LandingResolver` logs in with those credentials, so the visitor sees the machine card and its manual without an account. The guest URLs are generated by the backend (see [backend/README.md](../backend/README.md)).

**Chat streaming.** `useChatStream` reads the `POST` stream with `fetch` + `ReadableStream`, because `EventSource` only supports `GET`. How each event is used:

| Event | Effect in the UI |
|---|---|
| `start` | saves the `thread_id` of the conversation |
| `thinking` | fills the collapsible "reasoning" panel |
| `token` | appends text to the answer |
| `reset` | clears the partial answer before the recovered one |
| `sources` | turns the manual sources into citations; clicking one opens the PDF at that page |
| `error`, `done` | end of the turn |

## Structure

```
frontend/
├── src/
│   ├── pages/        # one component per route (+ ChatWorkspace layout)
│   ├── components/
│   │   ├── chat/     # bubbles, input, history drawer, suggestion chips
│   │   ├── manuals/  # PDF viewer, toolbar, full-text search
│   │   └── ui/       # Button, Header, ProtectedRoute
│   ├── context/      # AuthContext (session), MachineContext (fleet, active machine)
│   ├── hooks/        # useChatStream (SSE), useChatApi (conversation history)
│   ├── models/       # ChatMessage
│   ├── assets/mocks/ # data for mock mode
│   ├── stories/      # Storybook stories
│   └── styles/       # tokens.css (colors, spacing, fonts) + one CSS file per component
├── nginx.conf        # SPA fallback for production
├── Dockerfile        # build with Vite, serve with Nginx
└── vite.config.js    # PWA, @ alias, dev server, Storybook tests
```

`@` is an alias for `src/` (`import Button from '@/components/ui/Button'`).

## Running

### With Docker

From the repo root, `docker compose up -d --build` builds the bundle and serves it with Nginx on [localhost:8080](http://localhost:8080). The image doesn't read the root `.env`, so `VITE_API_URL` keeps its default `http://localhost:8000`.

### Locally

Requires Node.js 20+ and the backend on port `8000`. The `VITE_*` variables are read from the root `.env`.

```bash
cd frontend
npm install
npm run dev
```

The dev server runs on [localhost:3000](http://localhost:3000) and is also reachable from the LAN (`http://<your-ip>:3000`), useful for testing QR scanning from a phone.

| Variable | Default | Notes |
|---|---|---|
| `VITE_API_URL` | `http://localhost:8000` | backend URL |
| `VITE_USE_MOCK` | `false` | `true` uses the data in `assets/mocks/` and a simulated stream, without backend |

Other commands:

| Command | What it does |
|---|---|
| `npm run build` | production build in `dist/` |
| `npm run preview` | serves the production build locally |
| `npm test` | Storybook tests with Vitest in headless Chromium (needs `npx playwright install chromium` the first time) |
| `npm run lint` | ESLint |
| `npm run storybook` | Storybook on port `6006` |

## Tests

The stories in `src/stories/` are also the tests: Vitest renders each one in a real Chromium browser through Playwright. Without installing Node locally, run them in Docker from the repo root:

```bash
docker run --rm -v "$PWD/frontend":/src:ro mcr.microsoft.com/playwright:v1.61.1-noble sh -c "mkdir /app && cd /src && tar --exclude=node_modules -cf - . | tar -C /app -xf - && cd /app && npm ci && npm test"
```

## Known limitations

- The `denied` stream event (tool refused by the access model) is not shown as a separate notice; the user only sees the assistant's text.
- The backend URL is fixed at build time (`VITE_API_URL`): the Docker image only works when the browser can reach the backend on `localhost:8000`.
